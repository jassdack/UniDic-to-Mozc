# eval — Mozc ユーザー辞書の測定ツール

> [!NOTE]
> **このツール群は、任意の Mozc ユーザー辞書に使えます。** 本プロジェクトの辞書に
> 限りません。`読み / 表記 / 品詞 / コメント` の4列 TSV であれば対象にできます。
> 自作の辞書、他プロジェクトの辞書（mozc-ut 等）の評価にもそのまま使えます。

## できること

| スクリプト | 測るもの | Mozc の起動 |
| :--- | :--- | :--- |
| `measure_injection.py` | 辞書が各読みに何件の候補を注入するか | 不要 |
| `measure_conversion.py` | 辞書の有無で第1候補がどう変わるか | **必要** |
| `measure_coverage.py` | 辞書のうち何割が Mozc に無い語か | **必要** |
| `scan_system_coverage.py` | 全件走査して重複登録を洗い出す | **必要** |

## 手早く試す

```bash
# 1. 静的な測定（依存なし・すぐ動く）
python eval/measure_injection.py YOUR_DICT.tsv --testset YOUR_TESTSET.tsv

# 2. 実変換の測定（Windows。対象辞書を Mozc にインポートしておく）
pip install grpcio-tools
python eval/fetch_mozc_protos.py
python eval/measure_conversion.py --testset YOUR_TESTSET.tsv
```

テストセットは `読み<TAB>期待表記<TAB>カテゴリ` の3列です。カテゴリ名は任意で、
集計の見出しに使われるだけです。同梱の `testset_words.tsv`（124件）が雛形になります。

# 測定の考え方


## 何を測るか

`measure_injection.py` は、生成した辞書が**利用者が実際に打つ読みに対して何を注入するか**を測ります。

各テスト読みについて、辞書の寄与を4分類します。

| 分類 | 意味 |
|:--|:--|
| 純益 | 期待表記だけを追加した（競合を増やさない） |
| 混在 | 期待表記を追加したが、同時に N-1 件の競合も足した |
| 純ノイズ | 期待表記を含まず、競合だけを足した |
| 無関与 | 何も追加していない（＝辞書に無い） |

## 測っていないこと

Mozc の**最終的な候補順位**は測っていません。それはシステム辞書と Mozc の
コストモデルが決めるため、本スクリプト単体から変換精度は断定できません。
「純ノイズ」は「誤変換を起こした」ではなく「求められない候補だけを増やした」の意味です。

実変換精度の測定には `mozc_server` への IPC 接続が別途必要です（未実装）。

## 使い方

```bash
# 現状の配布辞書
python eval/measure_injection.py path/to/mozc_unidic_merged_?.tsv

# 品詞を除外した場合との比較
python eval/measure_injection.py path/to/mozc_unidic_merged_?.tsv --exclude-pos 人名
```

## テストセット

`testset_words.tsv` は `読み / 期待表記 / カテゴリ` の3列。124件。
カテゴリは `common` `homophone` `verb` `tech` `spoken` `academic` `place` `person`。

**このテストセットは手で書かれたものであり、構成が結果を左右します。**
`common` と `homophone` に厚みを置き、辞書が勝つべき層（`place` `person`
`academic`）も意図的に含めています。追加・修正して再測定してください。

# check_pos_agreement.py — 2つの品詞判定経路の一致検証

`convert_unidic.py` には品詞判定の経路が2つあります。

- **JSON経路**: `config/pos_mapping.json` のルールを上から評価する
- **組込経路**: JSONが無い、またはどのルールにもマッチしない場合の決定木

両者は同じ結論を出す設計ですが、片方だけを直すと静かに乖離します。実際に、
実データ突き合わせで 1,739 件（判定対象の 0.44%）の乖離が見つかりました。

```
JSON        組込              件数  原因
助数詞      名詞             1,139  組込が「助数詞」を完全一致で判定し「助数詞可能」を取りこぼしていた
助数詞      アルファベット     144  同上（atm = 気圧の助数詞）
名詞サ変    アルファベット     362  アルファベット判定の位置の違い
名詞形動    アルファベット      94  同上
```

`tests/` の合成データは実データの組み合わせを網羅できないため、**リリース前には
必ず本スクリプトで `lex.csv` 全体を突き合わせてください。**

```bash
python eval/check_pos_agreement.py path/to/unidic-cwj/lex.csv path/to/unidic-csj/lex.csv
```

乖離が1件でもあれば終了コード 1 を返します。

## JSONルールの演算子

`pos_mapping.json` の `match` は、キーの接尾辞で演算子が変わります。

| 書き方 | 意味 | リストを渡した場合 |
| :--- | :--- | :--- |
| `"p1": ...` | 完全一致 | いずれかに一致 |
| `"cType_contains": ...` | 部分一致 | **すべて**含む（`["五段","カ行"]` など） |
| `"surface_endswith": ...` | 後方一致 | **いずれか**で終わる |

`_contains` と `_endswith` でリストの意味が異なる点に注意してください。1つの文字列が
複数の語尾を同時に持つことはないため、`_endswith` は「いずれか」以外に解釈できません。

# 実変換精度の測定（Windows専用）

`measure_injection.py` が「辞書が何を注入するか」を静的に測るのに対し、
ここでは**稼働中の `mozc_server` に実際に変換させて**比較します。

## 仕組み

Mozc の IPC はメッセージモードの名前付きパイプで、長さ接頭辞もハンドシェイクも
ありません。`commands.proto` の `Input` を1メッセージ書くと `Output` が返ります
（`Command` ではなく `Input` を送る点に注意）。

辞書の ON/OFF は `user_dictionary.db` を**空の辞書へ差し替えて** `RELOAD_AND_WAIT`
を送ることで行います。**ファイルを削除するだけでは切り替わりません** — 読み込みに
失敗した Mozc は既存のデータを保持するためです。元のファイルは必ず復元されます。

## 準備

```bash
pip install grpcio-tools
python eval/fetch_mozc_protos.py     # google/mozc から protobuf を取得・生成
```

生成物はリポジトリに含めません（Mozc は BSD-3 で、再配布には著作権表示が要るため）。

## 1. 変換精度の A/B

```bash
python eval/measure_conversion.py
```

テスト読みを辞書あり／なしの両方で変換し、第1候補の一致率を比べます。
計測対象の辞書が Mozc にインポート済みである必要があります。

**実測結果（124件・UniDic 202512 由来の既定辞書 267,413 語）:**

| 指標 | 辞書なし | 辞書あり | 差 |
| :--- | ---: | ---: | ---: |
| 第1候補一致 | 108 (87.1%) | 106 (85.5%) | **−2** |
| 上位10件に含む | 124 (100%) | 122 (98.4%) | **−2** |

改善 1 件 / 悪化 3 件。**日常語では辞書はわずかに精度を下げます。**
辞書なしで上位10件のカバー率が 100% であり、追加辞書が入り込む余地が
そもそも無いためです。

## 2. 辞書が本当に足している語の測定

```bash
python eval/measure_coverage.py path/to/mozc_unidic_merged_1.tsv -n 2000
```

辞書からエントリを無作為抽出し、辞書なしの Mozc が同じ変換を出せるかを調べます。

**実測結果（2,000 件抽出）:**

| 分類 | 割合 | 意味 |
| :--- | ---: | :--- |
| 既存 | 51.0% | Mozc が元から出せる。重複登録で競合を増やすだけ |
| 追加 | 45.7% | 本当に変換を増やしている（全体で約 122,000 語） |
| 未達 | 3.2% | 登録しても上位に届いていない |

品詞別では `アルファベット` の追加率が 93.8% と最も高く、`名詞サ変` は 28.0% と
低い（＝ほとんど重複）。

## 3. 重複登録の洗い出しと差分辞書

測定2が示すとおり、辞書の約半分は Mozc が元から出せる語の重複登録で、
競合を増やすだけになっています。これを全件走査して落とすことができます。

```bash
# 全エントリを走査し、Mozc が既に出せるものを列挙する（26万件で約100分）
python eval/scan_system_coverage.py path/to/mozc_unidic_merged_1.tsv -o eval/system_covered.tsv

# その結果を使って差分辞書を作る
python converter_scripts/merge_unidics.py --exclude-list eval/system_covered.tsv   tsv/mozc_cwj.tsv tsv/mozc_csj.tsv merged/mozc_unidic_diff.tsv
```

走査は結果を逐次書き出すため、中断しても `--resume` で再開できます。

> [!WARNING]
> 走査中はユーザー辞書が空になります。異常終了した場合は
> `user_dictionary.db.abbackup` から手動で戻してください。

## 測定の限界

- テストセットは手書きの124件で、語単位です。文単位ではありません
- 学習履歴のない新規セッションで測っています
- Mozc のバージョン・システム辞書に依存します（測定時 3.33.6089.100）
- 「Mozc が出せる」の判定は上位K件（既定10）に含まれるかで行っています。
  K を変えれば重複と判定される範囲も変わります

# 調査して「対応不要」と判断したもの

## ASCII表記のエントリ（7,710件）

表記が半角英数のみのエントリについて、当初は「ノイズが多い」と見ていましたが、
調査の結果**対応不要**と判断しました。

| 形状 | 件数 | 実例 |
| :--- | ---: | :--- |
| 全大文字 | 4,135 | `えむぶいぴー→MVP` `あいあーる→IR` `しーえふえー→CFA` |
| 先頭大文字 | 1,921 | `げぜるしゃふと→Gesellschaft` |
| 全小文字 | 1,344 | `えっくすわいぜっとぜっとわい→xyzzy` |
| 記号混じり | 300 | `いれぶんす→11th` `ふぃーちゃりんぐ→feat.` |
| 1文字 | 10 | 単位記号 `ぐらむ→g` `りっとる→L` `ぼると→V` `ぱーせんと→%` |

「ノイズ」と見えていたのは `aiko` `AOKI` `Einstein` のようなローマ字表記の人名
でしたが、**これらはすべて品詞が人名であり、既定配布からは既に除外済み**でした。
残っているのは略語・外来語・単位記号で、いずれも IME で入力したい語です。

さらに `measure_coverage.py` の実測では、`アルファベット` 品詞の**追加率 93.8%**
が全品詞中で最も高く、Mozc がほぼ持っていない＝辞書内で最も価値の高い
カテゴリであることが分かりました。フィルタで落とすのは逆効果です。

# 差分辞書に関する注意

## measure_injection.py は差分辞書には使えない

`measure_injection.py` の「純ノイズ／期待表記のカバー」は、**辞書が期待表記を
供給する**ことを前提にした指標です。差分辞書は「Mozc が持つ語を除いたもの」
なので、定義上どの期待表記も供給しません。実際に測ると期待表記 0/124 に
なりますが、これは失敗ではなく設計どおりです。有効な比較は競合数だけです
（全辞書 8.2 → 差分辞書 4.8、−41%）。

差分辞書の良し悪しは `measure_conversion.py`（実変換の A/B）で判断してください。

## 除外基準 `--topk` の選び方

`scan_system_coverage.py` は既定で「Mozc が**上位10件**に出せるなら重複」と
判定します。この基準は**厳しすぎる場合があります**。

実例: `せっしょう → 摂政` は、Mozc 単体では上位10件に含まれるものの第1候補は
「殺生」でした。ユーザー辞書があると「摂政」が第1候補に上がります。つまり
この語は「重複」ではなく**順位を改善していた**のですが、`--topk 10` では
除外されてしまいます。

- `--topk 10`（既定）: 積極的に削る。26万語 → 13.7万語
- `--topk 1`: Mozc が既に第1候補にしている語だけを削る。削減幅は小さいが、
  順位改善の効果を失わない

用途に応じて選んでください。走査は 26 万件で約 70 分かかります。
